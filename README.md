# BOSS 岗位查询

按关键词和城市跨公司搜索，或输入公司名 / BOSS 公司主页链接查询指定公司的岗位。结果包含岗位、月薪统计和 CSV；跨公司搜索还提供按公司汇总。默认关键词为“前端”，指定公司后可清空关键词读取该公司的全部岗位。当前实现 BOSS，智联留到第二阶段。

## Windows 桌面版

桌面入口为 `desktop.py`，将现有页面放入独立应用窗口，在用户电脑上启动专用 Chrome。支持原生 CSV 保存框、独立用户数据目录、单实例保护和退出清理；不需要部署服务器。Windows 构建、依赖和使用说明见 [WINDOWS.md](WINDOWS.md)。可运行 `scripts/build_windows.ps1` 完成测试、打包和打包产物的离线验收，输出目录式应用及 ZIP。

网页和 CLI 入口继续保留。切换到本分支前启动的旧服务，请先退出再重启，以使用跨平台的服务锁。

## 启动

本项目在 macOS、Python 3.12 和本机 Google Chrome 下运行。首次创建环境，或更新已有环境后启动服务。

```sh
# 首次安装
conda env create --prefix ./.conda-env --file environment.yml
# 如果已有项目环境，用以下命令更新
conda env update --prefix ./.conda-env --file environment.yml --prune

conda activate ./.conda-env
python crawl.py serve
```

打开[本地岗位查询](http://127.0.0.1:8765/)。服务只监听本机，默认端口为 8765，也可指定 `serve --port 8766`。提交查询时才打开专用的有头 Chrome。请在该窗口扫码登录，看到自己的头像后点“我已登录”。首次按名称查找时，从候选公司中选一次。公司链接可以跳过选公司。选错同名公司时，勾选“重新选择同名公司”再查询；CLI 使用 `--reselect`。重新确认后覆盖该名称的映射。

```sh
python crawl.py query --company 字节跳动 --keyword 前端 --city 北京 --pages 1
python crawl.py query --company 'https://www.zhipin.com/gongsi/job/公司ID.html' --keyword '' --pages 5
# 省略公司：自动滚动搜索，直到明确结束或遇到验证/加载问题
python crawl.py query --keyword 前端 --city 深圳
# 先读取 3 批进行核对；批数与页面上显示的卡片数量无关
python crawl.py query --keyword 前端 --city 深圳 --batches 3
```

公司留空时进入跨公司搜索，不再要求选择候选公司。城市留空（或填“全国”）时向站点提交全国条件；填写城市时会转换为站内城市代码，未知城市明确报错。城市名称/代码来自 [BOSS 官方公开城市字典](https://www.zhipin.com/wapi/zpCommon/data/city.json)，`sites/boss_cities.json` 为 2026-11-04 提取的 374 项名称/代码快照，不包含定位信息；站点增加或调整城市时需更新此快照。

跨公司搜索默认“自动加载”（CLI `--batches 0`），通过滚动岗位列表触发后续加载，没有本地每日次数上限，也不受公司查询的 1–5 页上限影响。需要限定本次范围时可指定 1–60 批。监听覆盖整次搜索，按请求发起顺序处理响应，卡片离开视口或被回收不影响已经收到的岗位。核对请求地址或正文中的关键词、城市；没有明文条件时核对当前搜索页 URL，排除本次监听前的在途响应和推荐/公司接口，不逐家打开公司页。

仅当列表响应明确返回 `hasMore=false` 才标记“已读完本次搜索提供的结果”，不等于平台全量。达到自选批数、用户停止、登录失效、验证、重复响应、结构错误或加载超时时，保留此前完整读取的批次并标记“未读完”；仍可查看统计和导出 CSV。首批尚未成功时直接报错，不显示为零岗位。结果只存服务内存，不增加数据库、磁盘结果缓存或断点续采；沿用现有岗位链接去重。跨公司搜索不自动保存岗位响应样本。

CLI 打印汇总、岗位表格，并写入 `data/boss-查询编号.csv`。网页的“导出 CSV”下载同样的列。服务已运行时，CLI 自动连接该服务的工作线程，包含自定义端口。单独运行 CLI 时，会建立临时本地服务，命令退出后关闭。用 Ctrl+C 结束常驻服务。

查询开始前会检查专用 Chrome 会话是否可用。上次窗口已关闭或连接失效时，会自动重建一次，沿用原登录配置，无需先失败再点第二次。若查询过程中关闭窗口，本次查询停止并明确提示；再次提交时重新打开浏览器，不自动重复已发出的查询。检测到未登录或登录失效时，程序会把专用标签页切到前台并点击可见的登录入口，等待人工扫码；失效恢复后需重新提交查询，跨公司搜索此前收到的完整批次仍可导出。

原有的 JobPosting 读取命令仍可处理本地 HTML 文件或其他站点的指定 URL。`collect` 会拒绝直连 BOSS，包括从其他地址重定向到 BOSS 的请求。

```sh
python crawl.py collect examples/frontend.html --company 'A 公司'
```

## 数据口径

- 通过浏览器自然产生的搜索列表响应读取候选公司。在所选公司的职位页接收列表 JSON，或读取文档响应内嵌的 `data[0].brandJobInfo.jobList`。搜索页使用 `joblist.json`，公司页筛选和翻页使用 `brand/job/querylist.json`，两者均监听并记录请求次数。首屏解析使用语法树读取常量，排除页面中的推荐岗位，不执行内嵌脚本。
- 有关键词且页面提供职位筛选框时，逐字输入后提交筛选，筛选结果从第 1 页起计数，选择 1 页也会执行。打开公司页所需的初始请求仍记录次数，不占筛选结果页数。无筛选框时只在已读页面本地匹配，并在网页和 CLI 中明确提示。
- 默认“前端”只判断岗位名。标题含“前端”直接匹配；Web、H5、React、Vue、小程序需要同时出现“开发”或“工程师”等开发角色词，并排除后端、运营、Web3、全栈等标题。技能中的 Vue 或 React 不会把其他岗位算成前端。其他自定义关键词仍可匹配岗位名和技能。岗位链接去重。
- 月薪以人民币元计，默认 12 薪。最低、最高分别取各岗位上下界。中位月薪为各岗位区间中点的中位数。平均年薪月数只计算可解析月薪的岗位。年薪除以 12 折算为月薪。`10K以上` 保留月薪下限，上限为空；日薪、时薪、面议、空薪资、未知格式及不完整区间均排除在汇总之外。
- 查询结果不写入磁盘缓存。即使公司、关键词、城市、页数完全相同，也会重新读取网站，并记录实际请求次数、执行等待间隔。网页结果仅保留在服务内存中用于展示和 CSV 下载，重启服务后清空。

## 节奏和本地文件

- 不设置本地每日请求数或成功查询数上限。公司查询仍按用户选择的 1–5 页读取；跨公司搜索可选择自动加载或限定批数。成功查询和实际请求次数仅用于统计及查询节奏。`quota.json` 沿用文件名保存这些计数；旧文件中的 `company_limit`、`request_limit` 自动忽略，并在下次写入时移除，无需清空历史计数。
- 使用被动 `request` 事件记录公司页文档和列表接口请求，失败请求、页面自动发出的并行请求也如实计数，不因累计次数停止。网络观察采用事件监听，浏览器缓存保持默认行为。[Playwright 网络事件文档](https://playwright.dev/python/docs/network)
- 每日计数按本机日期换日。
- 翻页、筛选或读取下一批前等待 4–9 秒，两次查询相隔 20–60 秒；每 5 次再休息 3–5 分钟，已过去的空闲时间计入休息。
- 遇到安全验证即停止。公司查询请在项目 Chrome 中人工处理，再点“继续”；跨公司搜索会立即保留部分结果，下次提交查询时再确认验证状态。当天触发验证后间隔翻倍，不再降额或按验证次数锁定到次日。人工确认后须主动提交新查询。普通业务错误只报错停止，只有明确的异常访问提示、验证码、验证页或 HTTP 429 才记录风控，未知业务 code 和 HTTP 403 不直接记为风控。
- `profiles/boss/` 保存专用登录态。`data/` 存公司映射、请求计数、风控事件和导出文件。两者均已加入 Git 忽略规则。样本仅保存岗位白名单字段，招聘者信息、Cookie 和跟踪参数不写入结果或样本。

## 开发环境隔离

```sh
python crawl.py serve --dev
python crawl.py query --dev --company 公司名 --pages 1
```

开发服务默认使用 8766 端口。请求计数、事件、公司映射、样本和导出文件放在 `data/dev/`，浏览器使用 `profiles/dev/boss/`。正式入口仍使用 `data/`、`profiles/boss/` 和 8765 端口。两个入口各自通过进程锁复用对应服务。

此前 2026-11-04 的 5 次开发尝试及一次风控记录已原样归档到 `data/dev/legacy-20261104/`。后续测试统一在临时目录或 `--dev` 下进行。

## 验证

```sh
python -m unittest discover -s tests -v
# 可选：使用本机 Chrome 离线回放虚拟列表，全部请求在本地拦截，不访问 BOSS
BOSS_BROWSER_TESTS=1 python -m unittest discover -s tests -p test_search_browser.py -v
```

跨公司搜索测试覆盖超过 60 批的持续读取、旧额度文件兼容、POST 条件、乱序/在途响应、虚拟卡片回收、左右区域滚动、停止后的 CSV、登录失效时打开扫码入口、浏览器关闭和空结果。2026-11-04 开发环境真实搜索“深圳 / 前端”读到首批 15 个匹配岗位，验证了公司汇总和薪资展示；当前搜索页的请求条件不在 URL 明文中，左侧列表为 `.job-list-container .rec-job-list`，右侧详情也有岗位链接，需严格区分滚动区域。连续加载另有离线 Chrome 回放测试。

同日移除本地每日次数上限后，保留原有 30 次请求记录，真实搜索“广州 / JAVA”连续读取 3 批，得到 45 个匹配岗位、45 家公司，按本次选择的 3 批停止。确认旧额度文件不再拦截查询，修正后的左侧列表滚动可以触发后续批次。

`examples/boss_company_guest.json` 是本次从爱来公司页的首屏状态提取的真实访客样本，含 5 条岗位，薪资均为 null。测试会回放此样本。首次读到登录后的公司首屏、搜索列表或公司筛选列表时，分别生成 `examples/boss_company_first_page.json`、`examples/boss_joblist.json` 或 `examples/boss_company_querylist.json`，后续也可离线回放。开发模式下样本位于 `data/dev/examples/`。

列表等待超时时，错误提示会标明当前阶段（打开公司页、筛选或翻页），并在 `data/last_failure.json`（开发模式为 `data/dev/last_failure.json`）记录该阶段的请求路径、类型和响应状态。诊断不保存请求参数、Cookie、请求头或响应正文。

登录后的验收可使用一家公司链接，清空关键词，选择 1 页。在同一 Chrome 窗口对照岗位名和薪资原文，再确认表格、汇总和 CSV 一致。2026-11-04 已在开发环境使用“爱来（广东）技术发展有限公司 / 销售 / 不限城市 / 3 页”完成真实查询，得到 42 个匹配岗位，其中 41 个为月薪样本；前三条岗位名和薪资与页面截图一致。公司页的 `querylist.json` 响应和 `.options-pages` 下的箭头按钮已适配。其他公司及后续页面改版仍需按上述方式验收。离线测试另覆盖筛选页数、输入事件、翻页、请求计数、重复查询实时读取和错误处理。

登录确认最多 3 次，仍无法确认时提示检查页面结构。每次人工确认最多等待 5 分钟，超时即结束本次查询。若字段改名、列表不再加载或分页结构改变，查询会明确报错，避免把解析失败记作“零岗位”。

浏览器、节奏、存储、薪资计算分别位于 `browser.py`、`guard.py`、`store.py` 和 `salary.py`。BOSS 响应解析位于 `sites/`，跨公司滚动搜索位于 `sites/boss_search.py`，人工确认与工作线程位于 `service.py`。
