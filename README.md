# BOSS 岗位查询

按关键词和省份或城市跨公司搜索，或输入公司名 / BOSS 公司主页链接查询指定公司的岗位。结果包含岗位、月薪统计和 CSV；跨公司搜索还提供按公司汇总。网页和桌面界面的关键词默认留空，跨公司搜索需填写关键词；指定公司后可留空读取该公司的全部岗位。当前实现 BOSS，智联留到第二阶段。

## Windows 桌面版

桌面入口为 `desktop.py`，将现有页面放入独立应用窗口，在用户电脑上启动专用 Chrome。支持原生 CSV 保存框、独立用户数据目录、单实例保护和退出清理；不需要部署服务器。Windows 构建、依赖和使用说明见 [WINDOWS.md](WINDOWS.md)。可运行 `scripts/build_windows.ps1` 完成测试、打包和打包产物的离线验收，输出目录式应用及 ZIP。

网页和 CLI 入口继续保留。切换到本分支前启动的旧服务，请先退出再重启，以使用跨平台的服务锁。

### 查询工作台

网页与桌面版共用陶土暖色工作台：左侧设置查询条件，右侧展示薪资概况、城市进度和结果。可切换跨公司／指定公司查询，或重置下一次查询条件；编辑条件不会改变正在执行的城市计划。

结果支持“岗位明细／按公司汇总”切换。岗位表默认显示五组常用信息，“完整字段”可展开月薪范围、年薪月数和独立学历列；窄屏下表格可横向滚动。“统计口径与更多指标”保留最低／最高月薪和平均年薪月数，“查询记录”保留条件、批数和读取时间。刷新页面会恢复当前查询条件与进度；新查询期间保留的旧结果会明确标注，导出始终对应当前展示的那批结果。

## 启动

本项目在 macOS、Python 3.12 和本机 Google Chrome 下运行。首次创建环境，或更新已有环境后启动服务。

```sh
# 首次安装
conda env create --prefix ./.conda-env --file environment.yml
# 如果已有项目环境，用以下命令更新
conda env update --prefix ./.conda-env --file environment.yml --prune

conda activate ./.conda-env
python crawl.py serve
```

打开[本地岗位查询](http://127.0.0.1:8765/)。服务只监听本机，默认端口为 8765，也可指定 `serve --port 8766`。提交查询时才打开专用的有头 Chrome。请在该窗口扫码登录，看到自己的头像后点“我已登录”。首次按名称查找时，从候选公司中选一次。公司链接可以跳过选公司。选错同名公司时，勾选“重新选择同名公司”再查询；CLI 使用 `--reselect`。重新确认后覆盖该名称的映射。

网页和桌面版使用省市级联选择：选择省份默认查询全省，也可勾选多个城市（例如广东省的韶关、惠州）后点“确定”，或选择全国。切换省份会重置城市选择；取消所有城市后不能提交，需重新勾选城市或全省。跨公司查询只遍历所选城市，进度面板只列出本次目标；公司查询则按所选城市筛选已读取岗位。城市实时标记“未查 / 查询中 / 岗位已读完 / 未读完”；达到批数上限、加载异常或中途停止的城市不会算作已读完。勾选工商信息后，另行显示“工商信息已检查 X/Y 家”：按公司去重计数，包含复用已有字段或确认缺失的公司，不代表每家都获取到完整字段；等待、刷新和中断后保留实际检查进度。岗位已读完时，工商信息补充可能仍在进行，整个查询结束后才展示本次结果；导出 CSV 只使用已有数据，不触发二次查询。刷新页面可恢复当前查询进度和选择，修改表单不会改变正在运行的城市计划。

### 登录状态

已移除把浏览器配置名称当作账号的面板，包括名称输入、配置下拉框和独立的手动确认按钮。旧面板的添加/登录接口返回“页面已更新”的提示，不再由旧页面弹出登录窗口。

点击“查询岗位”后，程序在专用 Chrome 中检查真实登录状态：已登录直接继续查询；未登录时自动点击 BOSS 页面上的登录按钮，用户完成手机号／验证码或扫码登录后自动继续同一次查询，也可点击“我已登录”触发检查。页面不再提供独立登录入口。刷新项目页面可恢复当前查询和等待登录状态，等待期间可停止查询。

当前查询流程按 BOSS 页面实际状态判断是否需要登录，不再由旧配置中的 `ready` 标志锁死查询入口。日常 Chrome 与项目专用会话的登录状态不共享。登录入口不会清除已有访问暂停；历史查询结果仍可导出。

已有会话目录、暂停记录和查询结果继续保留。真实访问限制仍会停止查询，本地 CSV 导出不受影响；登录成功也不等于岗位访问一定可用。

项目使用本机安装的 Chrome，但专用配置与日常 Chrome 的 Cookie、登录和本地存储互不共享，因此日常浏览器能打开网页不代表项目会话也能访问。启动时明确启用 Chromium 沙箱；这修复了默认 `--no-sandbox` 设置，不代表平台一定允许访问。登录确认需要页面显示账号头像，不再仅凭旧 Cookie 判断成功；BOSS 的 `/web/passport/zp/403.html` 即使正文尚未显示也会立即按受限处理。

```sh
python crawl.py query --company 字节跳动 --keyword 前端 --city 北京 --pages 1
python crawl.py query --company 'https://www.zhipin.com/gongsi/job/公司ID.html' --keyword '' --pages 5
# 省略公司：自动滚动搜索，直到明确结束或遇到验证/加载问题
python crawl.py query --keyword 前端 --city 深圳
# 查询广东全省（原 --city 参数同时支持省份）
python crawl.py query --keyword 前端 --city 广东省
# 按省逐市读取，每市最多 3 批；设为 0 则等当前城市明确结束后才换市
python crawl.py query --keyword 运营 --city 广东省 --city-batches 3
# 先读取 3 批进行核对；批数与页面上显示的卡片数量无关
python crawl.py query --keyword 前端 --city 深圳 --batches 3
```

公司留空时进入跨公司搜索，不再要求选择候选公司。地区留空（或填“全国”）时向站点提交全国条件；填写“广东”或“广东省”时，将该省展开为省内城市，依次提交各城市代码并合并结果，不将省级代码传给站点搜索；填写“深圳”或“深圳市”只查询该市，未知地区明确报错。自治区支持简称和全称，例如“广西”“广西壮族自治区”。“吉林”沿用吉林市，“吉林省”查询全省；直辖市沿用原城市代码。

地区名称/代码来自 [BOSS 官方公开城市字典](https://www.zhipin.com/wapi/zpCommon/data/city.json)。`sites/boss_cities.json` 为 2026-11-04 提取的 374 项城市名称/代码快照，`sites/boss_locations.py` 中的 34 个省级代码于 2026-11-08 按该字典的 `zpData.cityList` 核对，不包含定位信息；站点增加或调整地区时需更新。指定公司时，地区条件按岗位城市所属省份或城市筛选本次已读页面，页数范围不变；薪资统计基于筛选后的匹配岗位，省份中位月薪仍按各岗位薪资区间中点计算。

省份查询默认每市不限（每市上限为 0），逐市查完，持续有新增岗位且翻页正常时不会因批数或总耗时截断。网页“省内每市上限”和 CLI `--city-batches` 可选设置 1–60 批；0 表示不限。连续 3 批无新增岗位或明确页码连续 3 批未前进、20 秒无有效进展（不含主动等待）、空批次未声明结束、卡片丢失、请求失败及服务端 5xx 会标记该城市未完成，并继续下一市。一次重复响应不会立即判为停滞；没有页码时根据新增岗位判断。登录失效、验证、用户取消及其他未识别错误仍停止整次查询，不会通过切市绕过。这个参数仅对省份查询生效，单市和全国查询保持原有自动加载方式。

结果分别显示“已查询城市”和“已读完城市”；达到每市上限或加载异常的城市列为未读完，异常原因保存在结果中并显示，遍历所有城市后仍标记部分结果，只有所有目标城市均明确返回 `hasMore=false` 才标记完成。切换城市时清空该市的监听队列、去重检测和超时状态，保持原关键词；岗位按链接在全省合并去重后计算薪资。每个岗位核对城市归属，排除省外及无法识别城市的岗位。省级代码只用于本地归属判断和城市规划：用户实站截图表明直接搜索广东省代码 `101280000` 返回空列表，而广州城市代码 `101280100` 有岗位。

跨公司搜索的总批数默认“不限（不建议）”（CLI `--batches 0`），表示整次查询没有总批数上限；按省查询时仍遵守每市批数设置。通过滚动岗位列表触发后续加载，没有本地每日次数上限，也不受公司查询的 1–5 页上限影响。需要限定本次范围时可指定 1–60 批；这是整次查询的总批数，省份查询在各城市间共享，不是每个城市的批数。达到总上限时停止整次查询并标记未读完；达到每市上限时继续下一市。不会把某市的空结果当作全省零岗位。监听按请求发起顺序处理响应，卡片离开视口或被回收不影响已经收到的岗位。核对请求地址或正文中的关键词、城市；没有明文条件时核对当前搜索页 URL，排除本次监听前的在途响应和推荐/公司接口。勾选“读取注册资本和成立日期”时，岗位列表读取结束后按公司去重读取岗位详情页；导出不访问 BOSS。

仅当列表响应明确返回 `hasMore=false` 才标记“已读完本次搜索提供的结果”，不等于平台全量。达到自选批数、用户停止、登录失效、验证、重复响应、结构错误或加载超时时，保留此前完整读取的批次并标记“未读完”；仍可查看统计和导出 CSV。首批尚未成功时直接报错，不显示为零岗位。结果只存服务内存，不增加数据库、磁盘结果缓存或断点续采；沿用现有岗位链接去重。跨公司搜索不自动保存岗位响应样本。

CLI 打印汇总、岗位表格，并写入 `data/boss-查询编号.csv`。网页的“导出 CSV”下载同样的列。服务已运行时，CLI 自动连接该服务的工作线程，包含自定义端口。单独运行 CLI 时，会建立临时本地服务，命令退出后关闭。用 Ctrl+C 结束常驻服务。

CSV 最前三列依次为“注册资金、所属行业、成立日期”，后面保留原岗位列。网页、桌面版和 CLI 均直接保存已采集的数据，导出不打开 Chrome、不访问 BOSS，也不触发工商信息补充。公司查询中，如果已经收到的公司职位页文档包含工商信息，会同时解析并保留在岗位结果中；网页和桌面版默认勾选“读取注册资本和成立日期”，在查询阶段使用已采集的岗位链接访问“查看更多信息”对应的详情页，同一家公司只读取一次；可取消勾选以避免额外详情请求。支持“注册资本／注册资金”和“成立日期／成立时间”标签，优先核对原岗位详情页招聘公司区域或工商名称链接中的公司 ID；品牌简称与工商全称不同但 ID 一致时仍读取，缺少链接时才使用名称包含关系兜底，ID 冲突、缺失或无法确认的字段留空。详情读取沿用 15–30 秒间隔和风控暂停，遇到取消、登录失效、验证或 429 停止，保留已采集岗位和已读取字段。CLI 使用 `--company-details` 开启；未传该参数的旧客户端保留仅查询岗位的行为。已有工商字段保留原值，缺失字段不作估算。

“所属行业”只在本地按岗位名称和技能推测，值附“按岗位估算”；通用岗位线索不足时显示“无法判断（岗位信息不足）”，不代表公司的工商登记行业。关闭专用 Chrome 或账号暂时不可访问时，已完成或已停止的查询结果仍可直接导出。再次导出也不会重启采集。旧客户端的导出准备接口只确认已有结果，不再启动网络任务；旧 CompanyExporter 兼容接口也只做本地字段整理，已移除逐家公司访问主页的代码。

查询开始前会检查专用 Chrome 会话是否可用。上次窗口已关闭或连接失效时，会自动重建一次，沿用原登录配置，无需先失败再点第二次。若查询过程中关闭窗口，本次查询停止并明确提示；再次提交时重新打开浏览器，不自动重复已发出的查询。网站自身安全中转回到岗位页但丢失关键词和城市时，仅在仍已登录、没有风控、尚未发出本次列表请求的情况下重新带入条件一次；再次丢失条件就停止，不重复恢复。普通网络错误、429、验证或账号受限不会触发此恢复。检测到未登录或登录失效时，程序会把专用标签页切到前台并点击可见的登录入口，等待人工扫码；失效恢复后需重新提交查询，跨公司搜索此前收到的完整批次仍可导出。

原有的 JobPosting 读取命令仍可处理本地 HTML 文件或其他站点的指定 URL。`collect` 会拒绝直连 BOSS，包括从其他地址重定向到 BOSS 的请求。

```sh
python crawl.py collect examples/frontend.html --company 'A 公司'
```

## 数据口径

- 通过浏览器自然产生的搜索列表响应读取候选公司。在所选公司的职位页接收列表 JSON，或读取文档响应内嵌的 `data[0].brandJobInfo.jobList`。搜索页使用 `joblist.json`，公司页筛选和翻页使用 `brand/job/querylist.json`，两者均监听并记录请求次数。首屏解析使用语法树读取常量，排除页面中的推荐岗位，不执行内嵌脚本。
- 有关键词且页面提供职位筛选框时，逐字输入后提交筛选，筛选结果从第 1 页起计数，选择 1 页也会执行。打开公司页所需的初始请求仍记录次数，不占筛选结果页数。无筛选框时只在已读页面本地匹配，并在网页和 CLI 中明确提示。
- 跨公司搜索，以及已在公司页筛选框提交关键词的查询，保留 BOSS 搜索返回的岗位，不再按岗位名称或技能二次过滤关键词；仍核对地区并按岗位链接去重。仅公司页没有筛选框、无法提交站点搜索时使用本地匹配：默认“前端”只判断岗位名。标题含“前端”直接匹配；Web、H5、React、Vue、小程序需要同时出现“开发”或“工程师”等开发角色词，并排除后端、运营、Web3、全栈等标题。技能中的 Vue 或 React 不会把其他岗位算成前端。“薪酬”等自定义关键词可匹配岗位名和技能。岗位链接去重。
- 月薪以人民币元计，默认 12 薪。最低、最高分别取各岗位上下界。中位月薪为各岗位区间中点的中位数。平均年薪月数只计算可解析月薪的岗位。年薪除以 12 折算为月薪。`10K以上` 保留月薪下限，上限为空；日薪、时薪、面议、空薪资、未知格式及不完整区间均排除在汇总之外。
- 查询结果不写入磁盘缓存。即使公司、关键词、城市、页数完全相同，也会重新读取网站，并记录实际请求次数、执行等待间隔。网页结果仅保留在服务内存中用于展示和 CSV 下载，重启服务后清空。

## 节奏和本地文件

- 不设置本地每日请求数或成功查询数上限。公司查询仍按用户选择的 1–5 页读取；跨公司搜索可选择自动加载或限定批数。成功查询和实际请求次数仅用于统计及查询节奏。`quota.json` 沿用文件名保存这些计数；旧文件中的 `company_limit`、`request_limit` 自动忽略，并在下次写入时移除，无需清空历史计数。
- 使用被动 `request` 事件记录公司页文档和列表接口请求，失败请求、页面自动发出的并行请求也如实计数，不因累计次数停止。网络观察采用事件监听，浏览器缓存保持默认行为。[Playwright 网络事件文档](https://playwright.dev/python/docs/network)
- 每日计数按本机日期换日。
- 搜索总批数和省内每市上限默认“不限（不建议）”，公司查询默认 1 页。翻页、筛选或读取下一批前等待 15–30 秒，两次查询相隔 60–120 秒，等待发生在打开浏览器之前；每 5 次成功查询再休息 3–5 分钟。已过去的空闲时间计入休息。不限批数可能产生大量访问，不建议使用；这些设置不是平台认可的安全阈值。
- 遇到账号“访问受限”、安全验证或 HTTP 429，停止整次查询，不切换城市、不自动重试。账号限制页面有恢复时间时按该时间暂停新查询，没有时间则至少暂停 24 小时；其他明确风控至少暂停 30 分钟。暂停状态保存至本地，跨日、重启、手动确认验证码不会提前清除，接口与页面同时拦截，仍可导出已有结果。时间到达后也不会自动采集。登录等待和登录失效恢复期间也检查风控跳转并记录暂停；首页及搜索页面导航返回 HTTP 429 同样立即停止。本次查询相关列表响应中的 429 或明确风控提示优先处理，不受正常结果的请求排序影响；即使前一个请求未返回、失败或超时，也不会继续切换城市。HTTP 429 的 `Retry-After` 支持秒数和 HTTP 日期格式，暂停时间取服务器要求、本地最低暂停和已有暂停中最晚的时间；缺失、无效或过期值沿用本地暂停规则，不自动重试。普通业务错误、未知业务 code 和普通 HTTP 403 不直接记为风控。降低访问量只能减少压力，不能保证不触发平台风控。
- `profiles/boss/` 保存专用登录态。`data/` 存公司映射、请求计数、风控事件和导出文件。两者均已加入 Git 忽略规则。样本仅保存岗位白名单字段，招聘者信息、Cookie 和跟踪参数不写入结果或样本。
